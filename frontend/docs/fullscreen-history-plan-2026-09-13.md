# 全屏 K 线：完整历史懒加载 · 方案书

版本 v1 · 2026-09-13 · 作者 Claude（设计与验收）· 实现：前端 Opus，后端索引 Codex

适用范围：Trader Foresight 里 lightweight-charts 那张真 K 线（`market-view.ts` + `trading-chart.ts`）。SVG 逐根回放页（relive/index.ts 的舞台）不在本方案内。

---

## 0. 一句话

窗口态只看「这一段」；按 F 进全屏，图先落在截图对应的那段（或相似匹配出来的那段），从这段出发往前往后拖，行情按视野一格一格接上，一直能拖到上市那天，也一直能跟到此刻正在跳的那一根。后端不存 K 线，只存「品种 · 周期 · 起止 · 边界」这类标记；K 线由浏览器直连交易所按需取，取不到再走后端。

## 1. 现状与问题

| 现状 | 问题 |
|---|---|
| 「之后 32 / 64 / 128 根」四颗按钮，每切一次重新请求、重建图 | 用户已取消这个交互；根数是个假选择，人要的是往后拖 |
| `history-feed.ts` 串行 1900 根一页，经后端 `/v1/market/data` 取 | 每页是一次后端→币安的实时往返；后端共用 600 权重/分钟，每 1000 根 5 权重，且响应里带一份重复的 `raw` 数组（体积翻倍），`Cache-Control: no-store` |
| 「完整历史」一键把上市到现在全拉进内存（上限 20 万根） | 1m 线几年就是几百万根，拉不完也画不动；不是懒加载 |
| 每次补数据 `appendBars` 整份 `setData` | 数据越多越卡；20 万根时每次补都要重算全部指标 |
| 全屏进入后视野停在原地 | 用户要求：进入全屏自动跳到截图段 / 匹配段 |
| `api/binance.ts` 已能从浏览器直连币安（1500 根/页，8 秒超时），但只用于重温页 | 全屏 K 线没用上这条最快的路 |

后端事实（只读核对，不改）：
- `POST /v1/market/data`：≤ 2000 根，无游标；超出返回 422 `interactive_market_limit_2000_bars`；同区间 15 秒去重缓存（最多 8 条）；并发 4；限流以 503 + `retry` 对象返回。
- 后端唯一落 K 线的地方是 `replay_bars`（24 小时过期、退出重温即删）。其余全是索引：`instrument_lifecycles`（`onboard_at` / `delivery_at` / `status`）、`attachment_locations`（截图定位段）、`coverage_segments`（特征索引覆盖）。
- 周期白名单 15 个，无服务端聚合。

## 2. 目标与不做

目标
1. 进全屏 100 ms 内落到锚定段（不等网络）。
2. 往任一方向拖，边缘补数据在热缓存下 < 200 ms、冷取 < 1.2 s 可见；拖动 60 fps。
3. 从 1m 到 1M 任意缩放，屏上 K 线数始终有界（≤ 约 3 000 根），不会因为「拉到上市」把浏览器拖死。
4. 图随时间往后长：视野贴着最新时，正在走的那一根实时跳动。
5. 后端零 K 线落库；新增的只有边界索引。
6. 交互达到 TradingView 级手感：惯性、吸附、测量、导航条、键盘全覆盖。

不做
- 不做绘图工具（趋势线、斐波那契）。
- 不做多品种叠加。
- 不改 SVG 回放页。
- 不在窗口态做懒加载（窗口态只有锚定段）。

## 3. 总体架构

```
┌─ market-view.ts（外壳：面板/工具条/全屏/锚定/导航条）
│    │
│    ├─ trading-chart.ts（画：lightweight-charts，只认「当前档位的一段连续 bars」）
│    │
│    └─ history/  新模块
│         ├─ tiles.ts        格子寻址、覆盖区间、并集/去重（纯函数，可单测）
│         ├─ lod.ts          档位阶梯、选档（带滞回）、跨档视野换算
│         ├─ scheduler.ts    优先级取数队列：可见 > 预取 > 行进方向，可取消
│         ├─ sources.ts      取数来源：币安直连 → 后端 /v1/market/data → 归档（只后端）
│         ├─ live.ts         最新一根：WebSocket kline 流 + REST 兜底
│         └─ store.ts        内存 LRU + IndexedDB 24h 热缓存（见 §7 决策点）
│
└─ 后端（Codex）：instrument_bounds 边界索引 + GET /v1/market/bounds（§6）
```

原则
- **图只吃一段连续数据**：`trading-chart` 永远只拿「当前档位、当前视野 ± 预取余量」这一段，几千根为上限。历史有多长和图无关。
- **时间是唯一坐标**：锚定段、截止线、判断时刻、视野保存全部按时间记，不按下标。换档、补数据、换品种都靠时间换算回来。
- **取数和画图解耦**：取数模块只维护「格子」和「覆盖区间」，画图按需向它要一段；两边通过 `onCoverage` 事件同步。

## 4. 数据层设计

### 4.1 格子（tile）

- 键：`(market, symbol, interval, tileIndex)`。
- 一个格子 = 固定的时间桶，桶长 `span = 1000 根 × 周期`。固定周期直接相乘；`1w` 用 1000 周，`1M` 用 1000 × 30 天（桶只是时间范围，桶内每根按交易所返回的真实开盘时间记，对齐问题不存在）。
- `tileIndex = floor(t / span)`，`t` 为毫秒。任意时间 → 唯一格子，任意视野 → 一串连续格子；缓存键天然稳定，可去重、可持久化。
- 格子状态：`empty | loading | filled | hole`
  - `filled`：`bars[]`（已收盘）、`complete`（这一桶是否取满：返回行数 < limit 且已覆盖到桶尾，或桶尾在未来）、`fetchedAt`。
  - `hole`：这一桶交易所没有数据。带原因：`before_listing`（永久）、`after_delisting`（永久）、`gap`（中段缺口，1 小时后可重试）。
- 覆盖区间：每个 `(market, symbol, interval)` 维护一条**有序不相交的时间区间表**（合并相邻格子）。查询「视野 [a,b] 缺哪几桶」是二分 + 线性扫描，O(log n)。

### 4.2 取数来源与顺序

1. **浏览器直连币安**（已有 `api/binance.ts`，扩展成按桶取）：`limit=1000`，权重 5；按 IP 计 2400 权重/分钟，和后端预算互不占用；无 `raw` 冗余，体积减半。并发上限 3。
2. **后端 `/v1/market/data`** 兜底：直连失败（451 / 跨域 / 8 秒超时）时切换，之后本次会话都走后端，不来回试。一桶 1000 根 < 2000 上限；串行 1 路；收到 503 按 `retry.after / retry.at` 等，不自己重试风暴。
3. **归档来源**（`source: 'monthly_archive'`，退市或早年品种）只走后端；这类品种行情不会再长，不开实时流。

响应合并：按 `start` 去重、升序；已存在的一根不被后来者覆盖（防止直连和后端两份数据对同一根的小数位不一致互相打架）。

### 4.3 调度器

输入：当前档位、当前视野 `[from, to]`（时间）、拖动速度（最近 300 ms 视野位移）。

优先级（小者先）：
```
0  可见区里空的桶
1  视野两侧各一屏的预取桶（先补行进方向那一侧）
2  行进方向再往前两屏（只在速度 > 0 时）
3  指标预热：左侧再补 maxPeriod × 1.5 根所在的桶（MA256 打开时才有）
```
规则
- 同一桶只在飞一次；桶离开「兴趣区」（可见 + 三屏）立即 `abort`。
- 直连并发 3，后端并发 1；每完成一桶就通知图补一次（合并到 `requestAnimationFrame`，一帧最多一次）。
- 遇到 `hole(before_listing)`：把该周期的地板记为「上市第一根」，之后不再往前发请求。
- 边界先验：进入时先问一次 `GET /v1/market/bounds`（§6，没部署就退回 `/v1/history/catalog` 的 `onboard_at`），拿到地板/天花板/已知缺口，省掉试探。

### 4.4 档位（LOD）阶梯

阶梯：`1m → 5m → 15m → 1h → 4h → 1d → 1w`（记录周期若不在阶梯上，如 3m / 2h / 8h，把它插进相邻位置；`1M` 只在人手选时用）。

选档规则（按像素）
- 当前档 `barSpacing < 2 px` → 升一档；`barSpacing > 14 px` 且更细一档存在 → 降一档。两个阈值之间不动（滞回，防抖）。
- 换档时：先把视野换算成时间区间 `[t0, t1]`，向数据层要新档位这一段（多半已在缓存，缺的桶按 §4.3 排队），`setData` 后用 `setVisibleRange({from: t0, to: t1})` 还原，肉眼看不到跳。
- 换档在图例里以文字提示「已切到 4h」（不弹 toast）。人手选周期（工具条「周期」chip）后**锁档**，缩放不再自动切，再按一次「自动」解锁。
- 每一档独立缓存、独立算指标（MA 在 4h 图上就是 4h 的 MA，与 TradingView 一致）。不做客户端聚合——聚合要求把底层全拉齐，正好违背懒加载。

结果：任意缩放下屏上 K 线 ≤ 视宽 / 2 px ≈ 1 000 根（1920 宽），加两侧预取也不过 3 000 根量级，`setData` 十几毫秒。

### 4.5 图的数据窗

`trading-chart` 持有 `window = { level, bars[] }`：当前档位里「覆盖区间 ∩ [视野左 − 2 屏, 视野右 + 2 屏]」的连续段。
- 数据层每次覆盖变化 → 重算 window → 与上次比较：只是右端追加用 `series.update()`（含最新一根的 `historicalUpdate`）；左端前插或中间补洞才 `setData`，并按时间还原视野（现有 `appendBars` 的下标平移逻辑保留作为后备）。
- 窗外的桶留在数据层的 LRU 里，不进图。

### 4.6 最新一根（图随时间往后长）

- 判定「贴近现在」：视野右端距当下 ≤ 1 屏。
- 贴近时开 `wss://fstream.binance.com/ws/<symbol>_kline_<interval>`（coin_m 用 `dstream`）。每条消息 → `series.update(openBar)`，节流 250 ms；`x: true`（收盘）→ 该根定稿写入格子、下一根作为新开盘根追加。
- 图右端被人钉住（视野右端 = 最新根）时才 `shiftVisibleRangeOnNewBar`，工具条「跟到最新」亮起；人往左一拖即解除。
- 断线指数退避重连（1s → 30s），标签页隐藏时关流；WS 不可用则每 15 秒 REST 取最后 2 根。
- 开盘根不进 IndexedDB（只缓存已收盘）。
- 图例增加「距收盘 12:34」倒计时和最新价闪一下的微动效。

### 4.7 内存与持久化

- 内存：每个 `(market, symbol, interval)` 最多 40 桶（4 万根），超出按最近使用淘汰；整页上限约 40 MB。
- IndexedDB 热缓存（决策点 D1）：库 `tf-klines`，store `tiles`，键 = 桶键，值 = `{bars, complete, fetchedAt, expiresAt}`；`expiresAt = fetchedAt + 24h`，与后端 `replay_bars` 同一口径；只存已收盘桶；总量上限 50 MB（LRU）；启动时清过期；「设置 → 行情」里给一颗「清空本机行情缓存」。命中时进全屏后补数据 < 50 ms。

## 5. 全屏交互设计

### 5.1 进入与锚定

- 锚定段 = 打开这张图时传入的 `ChartRequest.start_at ~ end_at`（截图定位段 `attachment_locations`，或相似结果的 `chart_request`），截止线 = `match_end_at ?? end_at`。
- 按 F / 点「全屏」：窗口态已有的这段直接复用（不等网络），240 ms 缓动把视野调成「锚定段占屏宽 60%，截止线落在 62% 处」——右边留出真实后续，左边留出上下文。缓动结束后调度器开工。
- 锚定段画成淡丁香色半透明**时间带**，上沿一枚小标签「截图这段 · 189 根」/「匹配这段」。带子按时间记，换档、补数据都不跑偏。
- 记录有判断时刻的：在截止线处放 `createSeriesMarkers` 箭头「记下判断」；有结果的再放触发 / 结束标记（来自 replay 的 `marks`，只画不算）。
- 顶栏候选切换（相似结果多段时）：同品种同周期只是把视野缓动到新段；不同品种则换数据空间，再锚定。

### 5.2 导航条（新增，全屏专属）

底部工具条上方一条 28 px 的画布导航条，画的是**该品种 1d 档从上市到现在的收盘线**（几千根，一两桶就够，也正好是 LOD 最粗档的数据，一份两用）：
- 已加载覆盖区间用亮色，未加载用暗色；锚定段一枚丁香色刻度；当前视野是一个可拖、可拉两端的窗口。
- 拖窗口 = 平移，拉边 = 缩放；点空白处 = 跳过去。
- 闲置 2.4 秒随工具条一起淡出（现有 idle 机制）。

### 5.3 手势与键盘

| 动作 | 桌面 | 触屏 |
|---|---|---|
| 平移 | 拖拽、Shift+滚轮、← →（一屏的 1/4） | 单指拖，惯性（`kineticScroll`） |
| 缩放 | 滚轮（以指针为锚）、+ −、[ ] | 双指捏合 |
| 复位到锚定段 | 0 / Home | 双击导航条锚点 |
| 到最新 | End | 导航条右端 |
| 到上市 | Shift+Home | 导航条左端 |
| 跳到日期 | G 弹一个日期输入 | 同 |
| 周期 | 1–7 数字键对应阶梯，A 回自动 | 工具条「周期」 |
| 十字线吸附 | M 切换 magnet | 长按出十字线（`trackingMode`） |
| 测量 | Shift+拖：显示 Δ%、根数、时长；松手 3 秒后淡出 | 双指长按拖 |

### 5.4 加载反馈

- 边缘桶在取时，图那一侧 80 px 宽的浅色斜纹呼吸条（不遮 K 线，不弹层）。
- 图例第一行进度「已加载 12,340 根 · 从 2023-03-01 起」保留；到地板时改成「上市 2023-03-01 起 · 全部在这」。
- 取不到：进度处变「更早的行情暂时没取到 · 重试」，点重试只重发那几桶。
- 直连不通自动切后端时，图例静默地把「币安」改成「币安 · 经服务端」，不打扰。

### 5.5 窗口态

- 只有锚定段 + 后面一小段真实后续（段长的 25%，最多一屏，不超过当下），一次请求 ≤ 2000 根，不懒加载。
- 「之后 32 / 64 / 128 根」四颗按钮删除。`stats` 里「后续 N 根：收盘 / 最高 / 最低」保留为只读数，N 取记录的 horizon（有 marks 就到 `marks.end_at`），否则 32。
- 工具条右侧留一句「全屏看完整历史 · F」。

### 5.6 无障碍与降级

- `prefers-reduced-motion`：缓动改瞬移，呼吸条改静态。
- 键盘可达：导航条可聚焦，← → 平移，Shift+← → 缩放。
- 视野状态（档位、中心时间、跨度）随 `choice` 一样进 `sessionStorage`，同一记录再开时回到上次位置（D3 决定是否上后端）。

## 6. 后端：只存标记（Codex 实施）

不新增任何 K 线表。新增一张边界索引和一个读接口：

```sql
CREATE TABLE public_market.instrument_bounds (
  market        text NOT NULL,
  symbol        text NOT NULL,
  interval      text NOT NULL,
  first_bar_at  timestamptz,        -- 实测最早一根开盘（比 onboard_at 准）
  last_bar_at   timestamptz,        -- 最近一次见到的已收盘根
  gaps          jsonb NOT NULL DEFAULT '[]',  -- [{start,end,seen_at}] 中段缺口
  verified_at   timestamptz NOT NULL,
  PRIMARY KEY (market, symbol, interval)
);
```

- 写入时机：后端自己经 `market::data` / replay 填充取到行情时顺手更新（观察到空首页 → `first_bar_at`；`coverage_complete=false` → 追加 gap）。浏览器直连取到的数据**不**回传更新（服务端无法核实）。
- `GET /v1/market/bounds?market&symbol&interval` → `{ onboard_at, delivery_at, status, first_bar_at, last_bar_at, gaps, server_now }`，权限沿用 `search.compute`。
- 前端没有这个接口也能跑（退回 `/v1/history/catalog` 的 `onboard_at` + 自己的 hole 备忘），所以它是加速项不是阻塞项。
- 可选（D3）：`PUT /v1/calls/{id}/chart-view` 存 `{interval, center_at, span_bars}` 作为用户偏好，跨设备回到上次位置。

已有且继续用的索引：`attachment_locations`（截图锚定段）、搜索结果 `chart_request`（匹配锚定段）、`instrument_lifecycles`（上市/交割/状态）、`replay_bars`（后端兜底的 24 h 临时缓存，不变）。

## 7. 决策点（2026-09-13 用户已全部按建议拍板）

| # | 事项 | 我的建议 | 影响 |
|---|---|---|---|
| D1 | 浏览器 IndexedDB 24 h 热缓存 | **做**。和后端 `replay_bars` 同口径（临时、过期即清、可一键清空），不算「保存 K 线」 | 需改 `api/binance.ts` 头部「不写 IndexedDB」的约定和后端 handoff 文档第 44 行的说法 |
| D2 | 允许比记录周期更细的档位（1h 记录能切到 15m/5m） | **允许**，阶梯双向，默认自动选档 | 更多桶、更多流量，但都在懒加载边界内 |
| D3 | 视野位置上后端（跨设备记住） | 先 `sessionStorage`，后端接口放二期 | Codex 工作量 |
| D4 | 直连币安失败后本会话固定走后端 | **是**，不反复试探 | 少数网络下第一次进全屏多等 8 秒超时一次 |

## 8. 落地分期与验收

### 一期（数据层 + 全屏锚定，约 3 天）
- 新建 `history/tiles.ts` `lod.ts` `scheduler.ts` `sources.ts` `store.ts`（内存版）；`api/binance.ts` 增加按桶取；`/v1/market/data` 兜底。
- `market-view`：删四颗按钮；全屏进入缓动锚定；锚定带 + 截止线；边缘呼吸条；进度文案。
- `trading-chart`：数据窗模型（§4.5）；跨档换算；`setVisibleRange` 按时间还原。
- 单测（node test）：桶寻址（含 1w/1M 边界）、覆盖区间合并与缺桶查询、合并去重、选档滞回、跨档视野换算、调度优先级与取消、hole 地板逻辑、后端 503 `retry` 处理。目标 +40 例。
- 验收：1h 记录进全屏 100 ms 内锚定；往左连续拖到上市，无白屏、无跳位；1m 品种拉到最粗不超过 3 000 根在图；断网只在边缘出现「没取到 · 重试」。

### 二期（活的最新一根 + 导航条 + 手势，约 3 天）
- `live.ts` WS + REST 兜底；跟到最新；倒计时。
- 导航条画布；键盘全表；测量；吸附；钉价位线；周期 chip 与锁档。
- 验收：贴最新时开盘根按秒跳动；离开右端流即关；导航条拖动与图双向同步；触屏长按十字线、捏合无抖动；`prefers-reduced-motion` 生效。

### 三期（缓存与后端索引）
- IndexedDB 热缓存 + 设置页清空；`GET /v1/market/bounds` 接入；可选 chart-view。
- 验收：再次进全屏补数据 < 50 ms；边界先验生效后不再向上市之前发请求。
