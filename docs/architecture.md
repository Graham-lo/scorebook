# 当前架构与最新需求决议

日期：2026-09-09。用户本轮明确要求优先于桌面旧 v2.0 计划书。当前交付范围为后端基础能力，Chat 调度和正式前端后续接入。

## 决议

1. 后端由 Python 改为 Rust：Axum/Tokio/SQLx。金融规则使用 BigDecimal，34 位有效精度、Half Even；展示比率 12 位小数。模型计算用浮点，不参与正式金融数值规则。
2. 采用模块化单体、独立 API / worker / vision 进程。数据库唯一业务事实源；复杂任务有租约、心跳、去重。模型失败不阻断原话入库。
3. 多人准备：每项私有资源带 owner_id，关联使用复合外键；认证主体来自服务端密钥校验，不能由请求 body 选择。现在是单机开发运行形态；公网身份认证、配额、分布式限流、RLS/数据库角色加强、集群对象存储尚未交付。
4. 行情统一币安合约，默认 USDⓈ-M。合约 catalog 按交易所 underlyingType 区分 COIN / EQUITY / COMMODITY / INDEX 等，不能按 ticker 外观猜资产。股票合约不是美股现货行情。
5. 不持久化 OHLC、逐笔行情或系统生成图。它们由 REST 按需获取、在内存中处理并丢弃。保存请求窗口、输入摘要、结果、特征向量、来源身份和版本；这改变了原任务书“完整行情输入包离线回放”约定。旧结果保留，但没有原输入时不能宣称逐字节重放；供应商历史订正可能改变后来重绘的图。
6. 用户上传截图属于用户的知识库证据，仍保存原字节。截图引用不是精确价格来源。系统临时图与用户原始图身份分开。
7. 截图找历史分两类：已记录案例库、币安历史窗口。前者保留原话/复盘链接；后者保留合约/周期/起止位置及特征，不存行情。
8. 大模型以后解释用户需求并决定调用工具。现在提供模型无关的明确参数接口和只读数据工具。索引生成是有界计算任务；无任意 SQL、文件路径、下单或转账工具。

## 图片检索

`candle-profile-v1`：192 维红绿蜡烛区域轮廓、幅度与斜率的确定性基础描述子。需要合适的图表区域，不保证识别所有配色、线图、指标画线；失败返回明确原因。

`dinov2-small-v1`：384 维本地视觉特征。模型 revision `150c8e7bb7cef2d30ec31b13a517af14840ee3f7`，权重 SHA-256 `ae1e99fcefd534ed978cdeb8326f08030c96e28b7a81ffcbc98a857c84d14be1`。保持全图比例，letterbox 到 224；不中心裁掉时间两端、不翻转方向。CLS + L2。模型空间不混用。

`hybrid-v1`：复盘库中两路各自检索，再做 RRF 排名融合；保留不可用分支。历史窗口目前明确选择一种模型，可分别检索再由后续编排融合。

pgvector 配有按模型维度区分的 HNSW 索引。当前查询使用过滤后精确余弦距离作为正确性基准，避免启用 ANN 后过滤漏候选。启用大规模 ANN 前必须测带用户/品种/周期过滤的召回率。尚未声称全库亚秒或某个准确率。

历史索引请求显式指定合约、周期、日期、窗口长度、步长、模型。单任务最多 5 万条源 K 线、1000 个窗口；worker 只发布完整构建完成的索引。大量历史通过拆分请求逐段建立，索引覆盖可查询。结果按半窗口间隔去重，返回重绘参数。

## 可追踪性与可靠性

- 原始 calls、attachments、reviews、outcomes 等有 UPDATE 拒绝触发器；改观点创建新 call，补充通过事件记录。
- 幂等键按 owner + operation 隔离；冲突内容 409。普通状态变更用 expected_revision。
- 附件文件先 fsync + 原子发布，再写引用；数据库未确认前不返回保存成功。进程崩溃可能留下孤立文件，不能产生已确认的悬空引用。
- jobs 的 SKIP LOCKED、租约 token、心跳和结果去重支持重新领取。历史任务先在内存计算再事务发布；原始结算用固定 job ID 防重。
- 图像编码并发 2、模型推理并发 1；数据库池每进程 12。生产配额、跨进程总限流和大量用户下的公平调度需后续压测与增强。
- 导出只包含当前允许持久化的知识库数据与文件。恢复到隔离数据库，不覆盖现有用户。密钥不导出。
