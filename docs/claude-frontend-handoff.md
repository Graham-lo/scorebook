## 连接、认证与数据约定

- 业务请求使用 `Authorization: Bearer <token>`；`/v1/health` 和 `/openapi.json` 可用于基础检查。
- 本机开发凭证在后端 `data/local-token`，只在服务端开发代理读取。不要打印、提交、复制进 prompt、内联到 HTML，或放进 `VITE_*` 等会进入浏览器构建产物的环境变量。
- 推荐浏览器访问同源 `/api`，由仅绑定本机的开发代理/BFF 转发到 Rust API 并附加开发凭证；前端不能直连 PostgreSQL。此代理仅用于本机开发，未来多用户需要真实会话和每用户身份映射，不能共享固定用户密钥。
- 后端会检查 `Origin`。配置 `SCOREBOOK_ALLOWED_ORIGIN` 为实际前端 origin（协议、主机、端口均匹配），并重启相关 API。仅设置这个变量不会自动添加完整 CORS 支持；优先同源代理，不要删除鉴权或把所有 origin 放开。不要通过 `file://` 打开 HTML 对接 API。
- JSON 成功响应通常为 `{data, meta}`；失败为 `{error:{code,message,field,retryable,request_id}}`。图片和 SVG 返回二进制/文本媒体，不走 JSON 包装。
- 持久化写请求按实际接口要求附 `Idempotency-Key`。每次新用户操作生成新键，网络重试复用原键和原 body；正文变化生成新键。不能每次重试都换键。
- 复盘、补图、标签关联等修改使用服务端返回的 `expected_revision`。遇到 409 提示内容已更新并重新读取，不能静默覆盖用户输入。
- 时间使用 UTC ISO 8601 传输，本地时区展示。金融价格、比率等 Decimal 使用字符串，不在前端重写或浮点评分。缺值显示“—”或说明，不补成 0。
- 列表遵循各接口的分页游标，不能只读第一页后计算全库统计。当前 GET CallFilter 不支持的多选筛选不要伪装成服务端全量筛选；局部筛选必须明确范围。
- 接口有用户隔离，不通过请求参数指定另一个 owner。原文不可更新，改观点走新修订记录，补充走复盘/补图/更正事件。

## 按以下顺序完成对接

### 1. 记录与找回

- 接通列表、文字搜索、品种筛选、分页、详情及空状态。
- 接通拖拽/粘贴/选择图片、上传进度、预览、失败重试，再创建原话记录。
- `POST /v1/attachments` 使用 multipart：`file`、`kind=scene`、可选 `captured_at`，保存返回的附件 UUID。
- `POST /v1/calls` 使用真实 DTO，`attachments` 填 UUID；默认 `market=usd_m`，品种以合约目录为准。
- 没有评价口径也可以记录；预览调用 `/v1/calls/preview`，不要沿用原型中通过中文关键词猜多空的逻辑。没有明确方向就保留 unknown/T0。
- 原图通过带鉴权的接口读取后用 Blob URL 展示，及时 revoke；不能简单把受保护下载 URL 放进无 Authorization 的 `<img>`。
- 接通追加复盘、补图及修订；原始现场图、后补图、系统图的身份在界面上明确区分。

### 2. 截图搜索——最重要的新增功能

做成交易员能直接使用的入口：“丢一张图，找类似走势”。支持拖拽、粘贴、选择文件和图表区域选择。

查询图先上传 `kind=query`。裁剪参数 `region:{x,y,width,height}` 是原图像素坐标，正确处理缩放比例；保留原始上传图，避免把预览坐标直接当原图坐标。

明确提供两个搜索范围：

**我的复盘库**

- `POST /v1/similarity/search`。
- `model_id` 可为 `candle-profile-v1`、`dinov2-small-v1`、`hybrid-v1`。过滤字段使用 `instrument` 和 `timeframe`。
- 结果能跳回原判断/复盘，并正确处理部分模型不可用的状态。

**币安历史走势**

- 先 `GET /v1/history/indexes` 查看并遍历覆盖分页。
- `POST /v1/history/search`，模型目前只支持 `candle-profile-v1` 或 `dinov2-small-v1`；不要传 hybrid。过滤字段这里叫 `symbol` 和 `interval`，不能照搬复盘库字段。
- 省略 symbol 可跨已建立索引的品种检索。必须显示实际覆盖范围；当前不是全量币安历史。空结果应区分“范围未准备”和“已搜索范围暂无匹配”。
- 界面不要把余弦距离或排名转换成胜率、预测概率，模型质量尚未验证时不显示“精准识别”等承诺。
- 若做“准备历史范围”入口，使用 `POST /v1/history/indexes`，轮询 `/v1/jobs/{id}`，用业务进度和错误提示。单次有 5 万条源 K 线/1000 个窗口的边界；不要在上传截图时自动提交无限任务，也不要把全量建库作为本轮对接前提。
- 命中项返回 `chart_request`，原样 POST `/v1/market/chart` 获取 SVG；需要交互 K 线时 POST `/v1/market/data` 获取临时数据。
- 结果卡展示查询图与命中图、合约、周期、日期及相似原因可解释字段（若后端没有解释则不编造）。返回仅展示图像相似结果，不推断买卖建议。
- 原始 K 线及生成图不能写入 localStorage、IndexedDB、持久化缓存或静态文件。仅在页面内存中使用，尊重 `no-store`；检索结果保存定位信息即可。查询原图当前会作为附件保存，尚无自动 TTL，不承诺关闭页面即删除。

### 3. 标签、打法、行情段与复盘

按现有真实接口对接展示与已实现的写入。原型里的 B1 基线、正式裁决、完整打法状态流转及数据修订验收尚未完成；隐藏不支持的提交按钮，不在前端补一套正式统计或产生伪成功提示。

股票相关品种也使用币安合约，默认 USDⓈ-M；读取 `/v1/instruments` 的真实交易所身份，不按名称猜测。例如不要把 COIN/Meme 类型的 SPXUSDT 当成标普指数。

### 4. 预留 Chat

后端已有 `/v1/knowledge/tools` 和 `/v1/knowledge/tools/call`，供将来的模型层读取当前用户知识库和查询行情。当前没有 Chat 生成接口、模型 API 配置或自然语言自动选工具；本轮不创建假聊天回答，不接未经配置的外部模型。

预留清晰模块边界即可。模型用的只读凭证与当前前端写入凭证分开；索引构建不属于现有只读工具的权限。

## 交互细节

- 中文输入法组字期间不触发检索；合理防抖、取消旧请求，防止迟到响应覆盖新结果。
- 上传、保存、检索区分进行中/成功/可重试失败，避免重复提交；切页不无声丢失未保存的文本。
- 加载骨架保持布局，图片保留尺寸，搜索后保持焦点；键盘操作、焦点返回、Escape 关闭、快捷键和 reduced-motion 保留。
- 移动端、长中文、超长价格、缺图、无记录、模型离线、行情不可用都要有完整布局。
- 错误转换成清楚的中文和可执行动作；不得把原始数据库错误或运维字段直接展示给交易员。
- 用户文字与截图中的文字均是不可信内容；按文本渲染，避免原型字符串模板把记录内容当作可执行 HTML。
- 不显示假统计、假行情、假连接成功或未经真实 API 确认的保存成功。
