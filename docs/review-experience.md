# 复盘体验与接口约定

这是给前端实现的业务交互规范。后端状态和接口已经提供；此文件不表示前端交互已经完成。

## 从每天的使用顺序设计

入口呈现“待复盘、继续填写、已完成、稍后处理”，默认待复盘。不要用总分、排行榜、连续打卡压力或运维统计占据首屏。交易员首先看到原判断摘要、品种/周期、记录时间、原图以及此次需要复盘的原因。没有评价标准也可以记下经验，不强迫用户先填完整策略表。

队列来自 `GET /v1/review-queue?bucket=needs_review|in_progress|completed|snoozed|all&limit=20`，使用 `next_cursor` 加载。顺序固定为记录提交时间倒序；状态变化后重新取第一页并保持当前详情，不在用户输入时突然跳走。计数不能用当前页长度冒充全库数量。队列的 `reason` 为 `first_review / continue_draft / new_outcome / reviewed`，分别解释为“还没有复盘 / 继续上次内容 / 有新的结果 / 已复盘”。稍后处理是提醒状态，`reason` 保留回到列表后的真实原因。

详情以原话和原图为视觉中心，编辑区是“这次看到了什么、下次怎么做”，然后是与上次的行动关系。`vs_last` 取 `did / did_not / new / keep`；有一次明确选择即可发布，不要求每段都写满。`note` 或 `better_play` 至少一项有内容。草稿可暂时完全空白。

## 草稿状态必须可信

1. 打开编辑区，读取 `GET /v1/calls/{id}/review-draft`。返回 `call_revision`、当前结果的 `current_outcome_ids`、持续递增的 `draft_revision` 和可为空的 `draft`。发布或丢弃之后时钟也不归零。
2. 用户停顿约 800 ms 后保存，失焦时补一次。每条记录的保存请求串行；有新内容时合并尚未发出的请求。`POST .../review-draft` 携带 `expected_draft_revision,note,better_play,vs_last`。
3. 每次内容变化使用新的 `Idempotency-Key`；同一请求网络重试复用原键和正文。收到成功前显示“保存中”，收到服务器确认才显示“已保存”。响应包含 `revision,updated_at`；完整草稿在 GET 中读取。时间展示以服务器时间为准。
4. 自动保存不增加原判断的 `revision`，不生成正式复盘、不改评价结果。关闭再打开会恢复服务器已确认的草稿。
5. 网络失败保留编辑器内容，显示“尚未保存，重试”。离线本地副本如需实现，使用当前用户和记录隔离的存储，登出清除；不能声称已经同步。页面切换保留选中记录、文字选择、滚动位置，避免上传/保存完成后抢焦点。
6. 409 `draft_revision_conflict`：暂停自动提交，读取最新草稿，保留本地文字，让用户比较并选择如何合并。不能自动拿新版本号覆盖远端。取消 fetch 不意味着服务器没有完成写入。

`POST .../review-draft/publish` 携带 `expected_draft_revision,expected_call_revision,expected_outcome_ids`。成功后返回正式复盘 ID、原判断的新 revision、后续草稿的 draft_revision；关闭编辑状态、更新队列，提供“查看这次复盘”，不要立即跳到下一条。发布失败不会清空草稿。`expected_outcome_ids` 必须是编辑时用户看到的结果 ID 列表；结果更新后返回 `review_outcomes_changed`，保留文字并让用户查看新结果，再确认发布。直接 `/v1/reviews` 也要求此字段，不能静默把用户的复盘绑定到未看过的结果。

`POST .../review-draft/discard` 携带 `expected_draft_revision`。有内容时由前端提供明确的放弃提示。仅移除当前草稿，原判断与历次正式复盘保留；草稿版本号继续增加，防止旧页面的迟到保存把草稿复活。

## 结果变化和提醒

正式复盘关联当时采用的评价结果版本。供应商故障和未到期属于处理状态，不伪装成交易判断失败。新的正式结果、或明确的数据订正成为当前结果之后，尚未讨论这个版本的记录重新进入“待复盘”。没有评价标准的 T0 自动处理完成不会把已完成的文字复盘重新打扰一次。

再次打开时并排呈现“当时的判断 / 这次补充”，不要改写历史复盘。`current_outcomes` 是当前正式结果，`outcomes` 包含历史版本和规则回放，不能直接取列表最后一项当正式结果。复盘发布时附带的结果引用也是解释历史页面的依据。

`POST /v1/calls/{id}/review-reminder` 使用 `expected_revision,until`。`until` 是未来一年内的 UTC 时间；null 清除提醒。队列返回独立的 `preference_revision`。发布复盘自动清除稍后提醒并推进其版本；旧页面不能悄悄恢复它。提醒到期后回到相应队列，目前没有系统推送通知。

## 长期历史不阻塞详情

`GET /v1/calls/{id}` 返回事件、复盘、历史结果各自最新 20 条；数组内部按旧到新排列，并返回 `history_pages.<kind>.next_cursor`。`current_outcomes` 保留每个判断口径的当前 head。

加载更早记录调用 `GET /v1/calls/{id}/history?kind=reviews|outcomes|events&cursor=...&limit=20`。后续页按新到旧返回；显示时按页面需要转换顺序，保持可见锚点，不能重复或漏掉相同时间的两条记录。UUID 和提交时间参与稳定排序。事件流用于解释用户的操作变化，不要把所有审计事件直接暴露为主界面。

## 截图、行情和搜索

原始现场图、后补图、查询图、系统重绘图身份不同。图片预览支持放大、平移、快捷关闭、回到原缩放；裁剪选择保留原图，用原图像素坐标传 `region`。上传失败保留本地预览，并允许单独重试。

搜索分“我的复盘库”和“币安历史走势”。相似度不是胜率，不显示“有 90% 概率上涨”。结果卡优先显示图形、时间/周期、原判断与复盘入口。模型不可用时说明具体搜索暂时不可用，不能后台改用另一模型并显示相同结果标签。

系统图通过币安合约 REST 即时重绘，前端不要写入持久缓存或把它混成用户原图。切换结果时取消不需要的显示更新；即使较早的请求后返回，也不能覆盖当前选中的图。价格是 Decimal 字符串，时间传 UTC、按用户时区显示。完整覆盖查询为 `/v1/history/coverage`；不能把“已准备的部分历史”写成“搜索了币安全部历史”。

## 状态文案

| 后端含义 | 交易员看到的表达 | 交互 |
|---|---|---|
| 等待结算时间 | 到期后补充结果 | 可以先写复盘 |
| 正在取得证据 / 暂时请求失败 | 行情暂未就绪，稍后继续 | 保留原话和草稿 |
| 缺少明确口径 | 可以补充判断条件 | 不要求删除重建原记录 |
| 暂未支持的持续条件监控 | 该类自动跟踪尚未开放 | 允许文字复盘 |
| 历史区间准备中 | 正在准备这段历史 | 展示已完成范围，可暂停 |
| 无匹配结果 | 暂未找到类似结构 | 保留查询图、区域和筛选 |
| 草稿冲突 | 这条复盘已在另一处更新 | 保留本地文字并比较 |

界面不出现 worker、lease、attempt、generation、向量维数、数据库审计等工程字段。功能完成以用户可恢复、可解释的状态为准。前端还需实测慢网、双标签页、输入法合成、键盘导航、移动端软键盘、空白和很长内容、时区切换、图片加载失败及减少动态效果偏好。

## 视觉和细节验收交给真实页面

桌面使用安静的列表与阅读区，原图和文字占据主要空间；编辑器避免表格化必填项和密集边框。窄屏进入单条详情时保留返回后的列表位置。颜色只表达选择和确实需要用户处理的状态，相似度、结果和保存状态不靠红绿两色区分。

首次使用先允许记下一段话或一张图，再逐步补充；首次复盘清楚表达“本次新发现”，不要让没有上次记录的人猜 `vs_last`。复盘完成后允许继续查看、补充另一篇复盘，不能用编辑原文的方式改变正式历史。原图、后补图和这次总结用时间关系串起来，避免横向铺满所有内部字段。

输入法合成期间不截取半个汉字进行提交；发布前先等待最后一次草稿保存确认。按钮在提交期间防止重复点击，但网络重试仍依赖幂等键。保存状态使用低打扰的文字，失败时就近显示重试；不要每次自动保存都弹 Toast。搜索容量繁忙时保留输入，按服务器重试提示等待，不清空结果、不切换模型。

Claude 交付页面时至少逐项验证：

| 场景 | 用户应看到的结果 |
|---|---|
| 写到一半关页，再次进入 | 最后一次服务器确认的内容和对应记录都能恢复 |
| 保存期间快速切换记录 | 两条草稿不会串写，晚到响应不抢当前焦点 |
| 两个标签页同时修改 | 本地文字保留，冲突需要明确合并 |
| 发布期间出现新的评价结果 | 草稿仍在，看过新结果后才能重新确认 |
| 已发布后旧页面继续自动保存 | 被旧版本校验拒绝，正式复盘不受影响 |
| 搜索无结果、图片失败、慢网 | 查询图、筛选和编辑内容保留，可就地重试 |
| 反复打开多年历史 | 历史按需加载，不一次灌入所有图片和复盘 |
| 键盘、移动端、减少动画偏好 | 焦点清楚，输入区域不被软键盘挡住，不依赖动画理解状态 |
