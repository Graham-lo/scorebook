# 一张截图搜索币安历史走势

## 用户体验目标

上传截图，选择或自动识别图表区域，返回相似的历史走势卡片。每项包含合约、K 线周期、起止时间、结构相似程度、覆盖范围和重绘参数。后续由模型解释用户意图并选择工具；当前后端参数接口已经建立。

“全部历史”应明确为：币安接口仍可取得、系统已完成索引的合约 × 周期 × 日期范围。不同窗口长度和步长产生不同覆盖密度；并不等于枚举任意起点、任意长度和所有图形变换。

## 当前数据流

```text
历史建库：币安 REST → 内存 K 线 → 滑动窗口 → 内存标准图 → 特征向量
                                                      ↓
                                PostgreSQL/pgvector：向量、版本、时间坐标、摘要

截图查询：用户原图 → 可选图表区域 → 同版本特征 → 已就绪窗口检索
                                                      ↓
                                合约/周期/时间 → 币安 REST → 内存重绘
```

用户原图属于知识库附件，可以保存。行情和生成图只在内存中存在。向量索引也会占用磁盘，因此“不保存行情”不等于“零存储成本”。

目前支持显式指定合约、周期、32–256 根窗口、步长和模型；每个索引任务最多 5 万条源 K 线、1000 个窗口。缺口窗口不参与索引。请求失败可由任务系统重试，只发布完整事务提交的结果。

`POST /v1/history/search` 可省略 symbol/interval，在已就绪范围内跨品种/周期查找。模型空间独立；历史检索目前选择一种模型，复盘库检索另支持两路融合。结果返回余弦距离，不把它包装成概率。

## 扩展为长期全量服务

下面是后续扩展设计，尚未实现或验收：

1. **覆盖规划**：根据交易所实际合约清单与接口可用历史生成任务；按合约、周期、日期分片。持久化进度与缺口，不保存行情。新数据增量索引，历史修订按摘要和版本重建。
2. **共享公共特征库**：币安历史特征可供多个用户共用，避免每个用户重复计算。用户原图/复盘及查询历史维持私有。当前所有索引仍按 owner 隔离；共享库需独立 schema、读权限和单独服务接口，不能直接放宽现有租户过滤。
3. **分层覆盖**：先建立主流合约与较粗周期，再增加小周期、多窗口长度和更小步长。每个阶段公布覆盖清单。批量调度必须有请求权重限流、429 退避、暂停和预算，不能每次上传图都同步抓取全历史。
4. **候选与精排**：验证带筛选条件的 ANN 召回率后启用向量候选检索；对少量候选实时获取 OHLC，按归一化路径、拐点位置、振幅比例和时间伸缩精排。原始精排输入在内存中丢弃。
5. **质量验收**：建立用户确认的相似/不相似样本集，分配色、周期、裁剪和标注遮挡统计 Recall@K、nDCG 与失败案例；时间切分避免未来信息混入。目标值依据首轮真实基线再确定。
6. **性能验收**：按实际窗口量测试索引时长、空间、峰值内存和查询 P95/P99。不同模型的向量维度和索引开销分别估算；现有文字查询基准不用于推断向量性能。

## 模型工具衔接

基础读取工具包括 `list_history_indexes`、`search_binance_history`、`get_market_data`、`render_market_chart`、`search_similar_charts` 和知识库来源读取。后续模型可以按“查覆盖 → 查相似 → 重绘候选 → 解释并引用来源”组织回答。

索引构建消耗计算与交易所额度，目前保持为明确的后台写接口。未来若开放给模型，需要独立的任务权限、预算和任务进度工具；只读凭证不会自动获得建库权限。未覆盖时应说明缺少的范围，不能回答“全历史没有相似走势”。
