本方案由主模型（Fable）定稿，交给执行代理实现。执行者按本文逐条落地，**不得改写任何用户可见文字**：所有页面名、按钮、状态词、空状态、提示语以 §3 文案表和 §4 术语表为准，逐字使用。有文案表没覆盖到的位置，先按 §3.0 的写法规则补一句最短的，并在交付说明里列出来给我审。

## 0. 诊断结论（为什么要这样改）

### 0.1 界面

1. **入口重复**：找东西有五个入口——顶栏「搜你说过的话」、找过去/按意思找、找过去/按图找、找过去/公开历史、找过去/问过去的自己，外加详情页每张截图上的「找同类局面」。它们底层只有两件事：按文字找我的记录、按图找（我的记录 / 币安历史）。
2. **同一概念多个页面**：「局面类别」和「我的做法」讲的是同一个东西（一类局面 + 我在这类局面上的打法）；「同一段行情」只是「我的记录」按品种分组；「实盘账本」和 cycle 是同一份成交数据。
3. **详情页动作太多**：顶部六个按钮（重温一遍 / 再写一条复盘 / 加标签 / 补后续走势 / 换一张现场图 / 加参考图）+ 每张截图两个工具（钉到真实行情 / 找同类局面），动作和它作用的内容分了家。
4. **文案**：每页顶部一段解释性长文（记录页、复盘页、长期统计、公开历史、按图找、设置），阶段名是动词短语（记录判断 / 持续观察 / 查看结果 / 完成复盘 / 沉淀做法），设置页露出模型名（candle-geometry-v2、dinov2-small-v1）。这与「展示页只放事实」的约定相违。
5. **重温里的对比图**：记录写的是 SKHYUSDT，里面的 MU 截图即使钉上了 MUUSDT，`replay.rs` 也会因为 symbol ≠ 记录品种而当作没钉（见 §5.3），所以对比图永远放不出来。

### 0.2 匹配算法（重温定位 / 刻舟求剑共用一套核心）

实测证据（MU 截图，附件 `b01394f2…`）：

- 后端 OCR **已经**读出了：`MU/USDT`、x 轴四个时间标签（`09-04 22:00 / 09-06 06:00 / 09-07 14:00 / 09-08 22:00`，横坐标 0.00 / 0.23 / 0.49 / 0.75）、右轴价格刻度（1050 / 1025 / 1000 / 975 / 950）、区间最高最低标注（1058.09 / 962.59）、最新价 981.76、副图标题（VOL… / MACD… / 持仓量…）。这些字**一个都没被用**——`analysis.rs::labels()` 只看顶部 30% 里的品种和周期。
- 用币安真实 1h K 线核对：high=1058.09 的那根在 2026-09-08 04:00 UTC，low=962.59 的那根在 09-04 12:00 UTC，可见窗口 ≈ 09-04 11:00 → 09-09 00:00 UTC，**约 110 根**，完全在已建索引的第 0 段里。所以不是索引覆盖问题，是匹配本身。
- 用真实 K 线做仿真：110 根的查询对 128 根定长窗口的**理论上限得分 0.85**（且最优窗口的结束时间还偏了 12 小时）；只要加 0.4% 的提取噪声，正确窗口就掉到 0.79，低于 0.85 自动接受线。实际提取还叠着均线、副图、广告条的干扰，得分 0.32。**定长 64/128/256 + 绝对阈值 0.85 这套设计，对真实截图在数学上就够不到。**
- 「都不是」之后把索引往更早推 768 根，是在错的方向上找：图本来就在第 0 段里。

其它代码级弱点（审计确认）：`×0.25` 方向硬悬崖（`chart_match.rs:398`）；min–max 归一化被单根长影线主导；分数无零分布校准，0.85 是拍的；单品种检索 SQL（`history.rs:509`）漏了 `bars_count` 过滤；副图剔除靠六个写死阈值，盲测带成交量副图命中 12.5% vs 不带 65.6%；`color()` 绝对亮度门槛 65 在暗色主题下全部失效；索引向量由真实 OHLC 算、查询向量由像素算，两条路不同源。

## 2. 逐页设计

原则（来自产品约定，必须遵守）：**展示页只放事实，不放引导语和解释段**；引导语只出现在「记一笔」和「写复盘」的填写流程里；空状态 = 一行说明 + 一个按钮，不放插画和大图标；所有宽度都要能用。

### 2.1 今天 `#/`

三块，按顺序：

1. **等答案**：还没有结果的记录，卡片显示 品种 · 方向 · 把握 · 记录时间 · 「怎么算对」一句。卡片点开进详情。没有则显示空状态 `今天没有等答案的判断`。
2. **该复盘**：市场已经给了答案但还没写复盘的记录（≤5 条，多了显示「还有 N 条」链到复盘页）。
3. **最近**：最近 6 条记录的紧凑行（品种 / 方向 / 结果标记 / 时间）。

页顶不放口号段。首页第一屏顶部一行只放日期和一个数字：`今天 9月12日 · 等答案 3 · 该复盘 2`。

### 2.2 记录 `#/find`

子页 **全部**：表格式列表（桌面）/ 卡片（移动）。列：时间 · 品种 · 周期 · 方向 · 把握 · 触发 · 结果 · 标签。行 hover 出现两个小动作：`重温`、`复盘`。筛选条：品种、方向、结果、触发（图在先 / 想法在先）、时间范围。

子页 **按品种**：同一品种连续的几次判断合成一组（原 episode 逻辑），组头：品种 · 起止日期 · 判断次数 · 对错计数。

子页 **成交**：原实盘账本页面内容，去掉顶部解释段；没有账户时空状态 `还没接交易所账户` + 按钮 `接一个账户`。

### 2.3 详情 `#/call/:id`

头部（一行事实 + 一行动作）：

- 事实行：`SKHYUSDT` `USDⓈ-M` · `看空` · `把握 80%` · `1h` · `图在先` · `9月11日 01:36`；右侧标签 chips（可点 `+ 标签`）。
- 动作行：只有一个主按钮 `重温`（有已对上的截图才可点；否则显示为 `先对上行情` 并滚动到截图卡）。其余动作下沉到各自阶段里。

进度条五段（术语见 §4）：`判断` → `走势` → `结果` → `复盘` → `打法`。每段是一个区块：

1. **判断**：截图卡（当时图，可多张）+ 原话 + 四格事实（方向 / 触发 / 把握 / 周期）+ `怎么算对` 一句。每张截图卡底部一行状态：`已对上 MUUSDT · 1h · 9月4日 20:00 – 9月9日 08:00`（时间显示为用户本地时区）或 `没对上` + 按钮 `对上行情`；右侧小链接 `找相似`（跳到找页并带上这张图）。卡片角标：`当时` / `之后` / `参考`，角标可点切换。
2. **走势**：钉上之后自动显示真实 K 线（当时窗口 + 之后 120 根，静态小图）；没钉则显示按钮 `补一张之后的图`。
3. **结果**：对错三选一按钮 `对` `错` `不算`，加一行 `按「怎么算对」判：…`。已判则显示结论和判定时间。
4. **复盘**：已写的复盘按版本列出（`第 2 版 · 9月12日`）；按钮 `写复盘`（打开复盘草稿流程，那里才有引导语）。
5. **打法**：这条记录所属局面的最新打法版本摘要 + 链接 `看这类局面`；没有局面则按钮 `归到一类局面`。

删除的东西：「你记录判断那一刻的截图，原样保留，没有被改过…」这类脚注全部删；「换一张现场图」改成截图卡右上角的 `…` 菜单（`换图` / `改成参考图` / `删除`）。

### 2.4 重温 `#/relive/:id`

五屏结构保留，屏名改为：`当时` → `逐根看` → `答案` → `复盘` → `打法`。

- 舞台默认**只画 K 线和成交量**；指标（MA / MACD / RSI）折叠在一个 `指标` 按钮里，默认全关，用户开过的记在本地。
- **对比图**：记录里每张已对上的截图在舞台上方是一排 tab（`SKHY 当时` / `SNDK 参考` / `MU 参考`），点谁播谁；播放进度按时间对齐（同一时刻）。这是 §5.3 后端修复后的前端部分。
- 舞台上方一行事实：`品种 · 周期 · 当前这根的时间 · O H L C`。不放解释。
- 底部控制：`◀ 上一根` `▶ 播放` `下一根 ▶`、速度 `1× 2× 4×`、`跳到判断时刻`。

### 2.5 复盘 `#/review`

三个子页各一个列表：

- **等市场**：有「怎么算对」但市场还没走到的；每行显示 `还差 N 小时到期限`（期限来自「怎么算对」的时限字段，没有时限则不显示）。
- **判对错**：市场已走到、还没判的；行内直接三个小按钮 `对` `错` `不算`。
- **写复盘**：已判、没写复盘的；行内按钮 `写复盘`。

全空时空状态 `没有要复盘的` 。页顶不放解释段。

### 2.6 经验 `#/stats`（战绩）

页顶四个大数字（带数字滚动动画）：`记录` `判对率` `图在先判对率` `想法在先判对率`。下方三张表（可切换）：按品种 / 按局面 / 按周期，每行：次数 · 对 · 错 · 不算 · 判对率 · 平均把握。最后一块：`把握 vs 结果`（把握分档 50/60/70/80/90 各档的判对率，条形图）。这些是「给直觉记分」的核心画面，只放数字和名词。

### 2.7 局面 `#/archive` 与 `#/archive/:id`

列表：每类局面一张卡：名字 · 一句定义 · 记录数 · 判对率 · 最新打法版本号。按钮 `新建一类局面`。

详情：顶部名字 + 定义（可编辑）；中间 `打法` 区：版本列表（`第 3 版 · 9月10日` + 正文），按钮 `写新一版打法`；底部这类局面的全部记录（同记录列表行）。原「我的做法」页的全部功能在这里。

### 2.8 找 `#/search`

一个大输入框：可输文字、粘贴或拖入图片、点右侧相机图标选图。

- 输入文字 → 结果两组：`说过的话`（语义 + 关键词，原 recall）、`标签和品种`（精确匹配）。
- 给图 → 先出一张识别小卡：`认出来：MUUSDT · 1h · 9月4日–9月9日`（能认出多少显示多少；认不出周期时出现四个 chip `15分 1时 4时 1日` 让用户点一下）；然后两组结果：`我的记录里`、`币安历史里`。每条结果：小 K 线图 · 品种 · 周期 · 起止日期 · 相似程度词（§4：`很像 / 像 / 有点像`）。
- 找页右上一个开关 `只看我的记录`（默认关）。
- 「问过去的自己」不再是页面；当本机配置了问答模型时，文字结果上方出现一行 `让它归纳这些记录` 按钮，否则不出现。

结果为空：`没有找到` + 一句 `换个说法，或者给一张图`。

### 2.9 记一笔（覆盖层）

保留现有一行完成的录入（品种、方向、把握、周期、图、话、触发）。这是唯一允许引导语的地方，但引导语也要短（见 §3.9）。

### 2.10 设置 `#/settings`

三组：

- **账户与备份**：导出、恢复、令牌。
- **行情与识图**：只显示状态行，不显示模型名。`行情来源 币安 · 已连上`、`识图 本机 · 可用/未启动`、`找相似的图 本机 · 可用/未启动`。有「启动」按钮就放，不能启动就只显示状态。
- **界面**：`涨跌配色`（`红涨绿跌` / `绿涨红跌`）、`截图时区`（默认「跟随本机」，可选 UTC 偏移；§5 的锚定定位会用它做首选偏移）、`动效`（跟随系统 / 关闭）。

## 3. 文案表（逐字使用）

### 3.0 写法规则（补文案时用）

- 名词优先，动词短语其次；一个按钮最多 5 个字，一个状态词最多 4 个字。
- 不写「你可以」「系统会」「这里是」；不写句号结尾的说明段；不出现 worker、job、lease、attempt、generation、向量、模型名、分数小数。
- 时间用「9月4日 20:00」格式，同年不写年；跨年写「2025年12月3日」。
- 数字用阿拉伯数字，百分比用 `%`。

| 位置 | 文案 |
|---|---|
| 品牌 | `Scorebook` 小字 `记分簿` |

| 主按钮 | `记一笔` |

## 5. 算法方案

### 5.1 目标

1. 重温定位（对上行情）：像 MU 这种币安 App 截图，**自动对上且不需要人点**；对不上的给出可信的候选，或直接让人填「最后一根的时间」。
2. 找（给图）：不再出现「真实截图永远够不到阈值」；结果按校准后的相似程度分三档，诚实地说「没有很像的」。

### 5.2 锚定定位（新的 locate 流水线，后端）

在 `crates/infrastructure/src/application/locate.rs` 的 `run()` 里，把「建索引 → ANN → 精排 → 阈值」换成下面的顺序。ANN 只在第 4 步兜底时才用。

**第 1 步 读锚点（新模块 `chart_search/anchors.rs`）**
输入 OCR 观测（`adapters::ocr::OcrResult`，已有）和几何（`chart_match::Geometry`，已有）。产出 `Anchors`：

- `symbol`：沿用 `analysis.rs::labels()`，但顶部条带从 `box[1] < 0.3` 放宽到 `< 0.35`，置信度门槛从 0.98 降到 0.9，并且只要 catalog 里命中唯一一个就算。
- `time_labels: Vec<{x_center, text, parsed}>`：在 `box[1] > 0.45`（图下半部）、高度 < 0.03 的观测里，用正则识别：`MM-DD HH:mm`、`MM/DD HH:mm`、`MM-DD`、`HH:mm`、`YYYY-MM-DD`、`YYYY/MM/DD`、`DD MMM`、`MMM DD`。年份缺省取「记录判断时刻」所在年（跨年取最近的一个）。允许左边被裁的 `-04 22:00`（前导缺月份时，用相邻标签推月份）。
- `price_labels: Vec<{y_center, value}>`：`box[0] > 0.8` 的纯数字观测（允许千分位、K/M 后缀）。同一 x 列里，纵向单调递减才成立；不单调的整组丢弃。
- `extremes`：图区内（不在右轴列）紧邻短横线的两个数：最大值在图区上半、最小值在下半（币安 App 的 `1058.09 —` / `— 962.59`）。识别为 `high_label` / `low_label`，可缺。
- `last_price`：右轴上带底色的那个数（OCR 拿不到底色，就取右轴列里**不在等距刻度序列上**的那个数）。可缺。
- `pane_cut_y`：副图标题（`VOL`、`MACD`、`RSI`、`KDJ`、`持仓量`、`OI`、`BOLL` 之外的副图词）里最靠上的一个的 `box[1]`。有它就把几何检测的 region 限制在 `y < pane_cut_y`、`x < min(price_labels.x)`。这一步放在 `chart_match::detect` 之前（在 `analysis.rs::evidence()` 里先跑 OCR，再按 OCR 定 region 调 detect；现在的顺序反了）。
- `utc_offset_candidates`：`[设置里的截图时区, 本机时区, 0, +8]` 去重。

**第 2 步 时间轴拟合**
若 `time_labels.len() ≥ 2`：最小二乘拟合 `t = a + b·x`（t 为秒，x 为图像归一化横坐标）。候选周期 = `b × pitch` 取最接近的合法周期（`domain::interval::ALL`），其中 `pitch = geometry.region.width / detected_candles`（归一化后）。若与 OCR 读到的周期冲突，以时间轴为准并把两者都写进结果。
最后一根的时间 `t_last = a + b·x_last`（`x_last` 为最右 glyph 中心），`t_first` 同理。对每个 `utc_offset` 候选各算一份。

若 `time_labels.len() == 1`，只能定周期不能定位置，进第 4 步。

**第 3 步 价格轴拟合（可缺）**
若 `price_labels.len() ≥ 2`：拟合 `price = c + d·y`。把几何蜡烛的像素 OHLC 换成价格 OHLC（`Candle` 加一个 `priced: Option<[f64;4]>`）。若右轴是对数刻度（相邻刻度比值恒定而差值不恒定），按对数拟合。

**第 4 步 取候选窗口并核对**
按优先级：

a. **极值指纹**（有 `extremes` 且有 symbol）：在 `[t_first − 3天, t_last + 3天]` 内取该品种该周期的 K 线（REST，一次请求），找 `high == high_label`（容差 = 1 个最小报价单位）的根和 `low == low_label` 的根。两根都唯一命中且顺序、间距与图上 x 位置一致（误差 ≤ 3 根）→ **直接判定**，窗口 = 以两根的 x 位置反推首尾。这是 MU 这类图的主路径。
b. **时间锚**（有 ≥2 个时间标签）：对每个 utc_offset 候选，取 `[t_first − 10%, t_last + 10%]` 的 K 线，在 ±10 根范围内滑动长度 `N = detected_candles ± 10%` 的窗口，对每个窗口打分（§5.4 新 `rerank`；有价格轴时用价格域直接比：`1 − 中位相对误差×k`，没有就用形状分）。取最佳。
c. **无锚**：沿用现有按需索引，但**检索长度改成自由长度**：对该品种在第 0 段（768 根）内，长度 `N ± 10%`（步长 2）、位置步长 1 的全部窗口直接算 §5.4 的分（≈ 768 × 12 = 9k 次 64 点带状 DTW，Rust 里几十毫秒），不经 ANN。ANN 与 64/128/256 索引对单品种定位不再使用（保留给全市场找）。

**第 5 步 判定与校准**
每次核对都得到「最佳分 s1、次佳不重叠分 s2、全部窗口分数分布」。判定：

- `sure`（写库，`matched_by='auto'`）：路径 a 命中；或路径 b/c 里 `s1 ≥ 0.75 且 s1 − s2 ≥ 0.10 且 s1 在该次分布里是 top-1 且 z ≥ 4`（z = (s1 − 均值)/标准差）。
- `likely`（不写库，返回一个候选让人点「就是这段」）：`s1 ≥ 0.6 且 s1 − s2 ≥ 0.06`。
- `weak`：其余，返回 ≤3 个候选 + 提示手填。

`SCOREBOOK_AUTO_LOCATE_MIN_SCORE/MIN_MARGIN` 两个环境变量改为默认 0.75/0.10，仅作用于路径 b/c。

**第 6 步 手填（我来填）**
`PUT /v1/attachments/{id}/location` 新增接受 `{symbol, market, interval, end_at, bars_count?}`：服务端按 `bars_count`（缺省用几何的 `detected_candles`）反推 `start_at`，取 K 线校验有覆盖后写入 `matched_by='user'`。响应带 `preview`：该窗口的 K 线（≤ 300 根）+ 与截图几何的对照分及词（`对上了 / 大致对上 / 对不上`，阈值 0.75 / 0.55）。前端定位面板的「对照」区用它。

### 5.3 重温放对比图（后端 replay.rs + 前端）

`replay.rs` 现在只接受 `symbol/market/interval` 与记录完全一致的定位。改为：`GET /v1/calls/{id}/replay` 返回 `tracks: [{attachment_id, kind, symbol, market, interval, window, bars…}]`，记录自身品种的当时图是第一条；每一张**已对上**的附件各一条（品种可以不同）。`replay_bars` 临时落库按 (symbol, interval) 各存一份，退出时一起删（沿用现有生命周期）。前端舞台按 §2.4 用 tab 切换 track，进度按时间戳对齐（不同周期时按时间取最近一根）。

### 5.4 匹配核心改动（`crates/core/src/domain/chart_match.rs`）

1. **去线**：在 `detect()` 连通域之前，先做一遍「细长横向像素段」抹除：任一颜色类的像素段，若水平连续长度 > 2×估计蜡烛间距（先用列投影的周期估计间距）且垂直厚度 ≤ 3px，置 0。这样均线（MA30/120/256 粉/绿/橙）不会把蜡烛粘成大块或切成两半。
2. **暗色主题**：`color()` 前先估背景（图像四角 + 中位色），若背景亮度 < 90，红绿判定改为相对背景的饱和度（`max−min ≥ 40` 保留，去掉 `r>65/g>65` 绝对门槛，改为 `通道值 > 背景对应通道 + 30`）。
3. **region 由 OCR 决定**（见 §5.2 第 1 步 `pane_cut_y`），`without_bar_panes()` 保留作兜底。
4. **归一化**：`normalized()` 的 `hi/lo` 改为 高的 98 分位 / 低的 2 分位（超出裁到 0..1 外也允许，不 clamp），避免单根长影线压扁全图。
5. **方向项连续化**：`rerank()` 去掉 `× 0.25`，改为 `cost += 0.15 × |netA − netB|`，`net = close[63] − open[0]`（归一化域）。
6. **红绿两种假设都试**：`rerank` 的调用方对 `red_up=false/true` 各算一次取高者，并把选中的写进结果（定位与找都适用；设置里的「涨跌配色」作为首选顺序）。
7. **自由长度**：新增 `pub fn sweep(query:&[Candle], bars:&[Candle], lengths: RangeInclusive<usize>, step: usize) -> Vec<(start, len, MatchScore)>`，供 §5.2 路径 b/c 与 §5.5 精排使用。
8. **`Candle` 加价格域**：`priced: Option<[f64;4]>`；`rerank_priced()` 在双方都有价格时用相对误差（`|Δ|/价格`）的中位数换算分：`score = exp(−200 × median_rel_err)`。

### 5.5 找（给图，全市场）改动

1. **索引窗口档位**：`history::LOCATE_WINDOWS`/universe 建索引改为 `[64, 96, 128, 192, 256]`（新增 96、192；`validate()` 允许 32..=256 不变）。查询时按 `N = detected_candles` 取最近的两档各查一次合并（`bars_count = ANY`），单品种检索 SQL（`history.rs:509` 附近）补上同样的 `bars_count` 过滤。已有的 4h/1d 索引需要补建 96/192 两档：写一个一次性作业 `history.universe` 的 `windows` 参数化，我验收时会跑。
2. **精排自由长度**：`chart_search/rerank.rs` 公开支在候选 (symbol, end_at) 附近 ±L/4 根、长度 `N ± 15%`（步长 4）用 `sweep()` 取最佳，替代「按索引窗口原样比」。`RERANK_BUDGET` 从 100 提到 300。
3. **校准**：新表 `chart_match_calibration(interval, bars_bucket, sample_score numeric)`；一次性作业对每个 (interval, 档位) 随机抽 500 个索引窗口当查询，跑同样的 ANN+精排（排除自身 ±L 根），记录 top-1 分。查询时对 top-1..N 的分算 `rarity = 该档位样本里低于此分的比例`。词：`rarity ≥ 0.97 → 很像`，`≥ 0.85 → 像`，`≥ 0.6 → 有点像`，其余不返回（`verdict: "none"` 时前端显示「币安历史里没有很像的」）。API 每条结果加 `match.rarity`、`match.level`，响应加 `verdict: found | weak | none`。
4. **结果合并**：同品种同周期、窗口重叠 > 50% 只留最高分一条；默认返回 5 条，`limit` 最多 10（与需求文档 3/5/10 一致）；32/64/128 根的后续走势照旧不参与排序。
5. **私有支（我的记录里）**：DINOv2 编码前用几何 region 裁图（去掉工具栏和副图），letterbox 保持。其余不动。

## 8. 补充（对照屏幕扫描报告 `docs/screen-map-2026-09-12.md` 后的修订）

### 8.1 「经验」多一个子页：统计

现状 `stats` 页承载的是**正式统计**系统（statistics runs：冻结成员表、六种下场、参照基准 B1、裁决），它是后端已有的数据模型，不能丢。处理：

- 「经验」子导航改为三项：`战绩` · `局面` · `统计`。
- `战绩`（§2.6）由前端从记录列表 + 结果聚合，只放数字；不依赖 statistics run。
- `统计` 保留现有 run 机制和三张 sheet，但**只删文案不删功能**：页顶三段解释（`stats/index.ts:142/146/150`）删掉；各 sheet 的说明段落全部删掉，只保留表格与数字；术语替换：`兑现比例 → 兑现率`、`六种下场 → 六种结果`、`成员表 → 样本`、`参照基准 B1 → 参照`、`等你裁决 → 待你定`、`数一份新的 → 新建统计`、`这一份统计 → 统计`；处理状态码（`stats/index.ts:623`）不得直接显示后端枚举，映射为 `还在算`。空状态：`还没有统计` + `新建统计`。
