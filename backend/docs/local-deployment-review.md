## Claude 原始集成测试

未改动 `app/test/integration.ts`，SHA256：4c955862ed0ddff5de3ee029693e55ad2c59584c91bf3a35d9043b1cff2d2ce5。测试在新建隔离数据库和存储运行，结束后清理，不混入主库。

实际结果：**81 项通过、3 项失败**。三项已进一步诊断，原始失败成绩仍保留，不改测试来美化结果：

1. 图像入库后立即查询，没有等异步索引完成，最初 0 条。6 个 embed 任务完成后，用相同输入和新查询身份得到 3 条。测试应等待目标截图的索引完成再断言召回。
2. 统计成员测试传 `limit=5`，v4 MemberFilter 不接受这个字段，实际 HTTP 400。去掉 limit 得到 HTTP 200、5 个成员。前端实际 statistics 客户端的字段是正确的；应修正测试使用 cursor。
3. 未配置 Chat 时，POST 接受一个持久 queued run，随后任务变为 blocked_capability，GET run 返回 chat_model_not_configured，answer=null。测试只检查 POST 必须报错，未读取异步状态；应按契约继续读取 run。并没有生成虚假答案。

证据：仓库 docs/frontend-integration-v4.log 和 .json。当前测试仍不能证明真实模型问答已接通。

## 八、周期约束、历史扩展与本机测试（2026-09-10 追加生效）

- 截图搜索必须明确一个周期，公开历史与个人记录两种来源都只匹配相同周期。周期缺失、空值或不支持时后端拒绝，不能默认 1h、沿用另一张图的周期或放开跨周期搜索。
- 当前支持 1m / 3m / 5m / 15m / 30m / 1h / 2h / 4h / 6h / 8h / 12h / 1d / 3d / 1w / 1M（币安合约 klines 全部 15 个周期，区分大小写：`1m` 是分钟，`1M` 是月）。识别结果只作为可确认的建议；界面须让用户选定周期再开始。无法可靠识别时必须手动选择。更换截图或框选区域后重新确认，未知周期的旧记录不混入结果。
- 新增“从上线到最新收盘”范围入口：读取已核实的合约上线时间，将起止时间对齐所选周期，随后可分段准备。没有可靠上线时间则说明原因并要求明确日期，不能推测。选择范围只读元数据，不启动下载或订阅。
- 用户最新决定：当前只交付功能，暂不扩展全市场索引、不启动历史自动同步。未来启用时可按品种、同周期及真实可取得边界分批扩展，不受原 90 天体验范围限制。
- 本机为 16 GiB 内存；实际测试限定 BTCUSDT、ETHUSDT 两个品种，1h / 4h 各 512 根近期已收盘 K 线，并额外验证 BTC 上线边界附近 128 根 1h K 线。测试实际从币安取数，不以纯模拟代替。
- 最新隔离测试：后端 96 通过、8 项显式跳过，前端周期单测 2 通过，构建和 Clippy 通过。真实测试临时建立 193 条特征，同周期筛选、跨品种去重、历史边界、后续图和“尚无后续已收盘 K 线”分支均验证。该结果不是匹配质量盲测或大规模性能验收。
