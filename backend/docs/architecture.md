# Scorebook v3 后端架构

模块化 Rust 单体，独立 API、worker、Python 视觉进程。PostgreSQL 17 是私有知识库的事实源，pgvector 提供私有图片和公共行情特征检索。此版本只有一套生产实现；迁移脚本处理历史数据，不保留旧 HTTP/SQL/模型算法退回路径。

## 编译边界

| 包 | 职责和依赖方向 |
|---|---|
| `scorebook-core` | 纯领域规则、Decimal 运算、图表构造、DTO、权限和应用/行情/原图存储端口；不依赖 Web 框架或数据库 |
| `scorebook-infrastructure` | 模块化用例、SQL 事务、PostgreSQL/本地存储/币安/视觉适配器；实现 core 端口 |
| `scorebook-http` | HTTP 路由、请求校验、认证中间件、统一响应和 OpenAPI；仅依赖 core，不访问 SQL 或网络适配器 |
| 根包 `scorebook` | CLI、API/worker 进程组合与生命周期；对测试重导出唯一实现 |

业务用例目前位于 infrastructure/application 中，因为它们直接组织 PostgreSQL 事务。不是把所有用例伪装成完全数据库无关的 domain 层。`Facade` 是单一组合入口；纯规则放 core/domain，未来模型工具和 HTTP 复用同一用例。`ops/check-boundaries.py` 和 CI 检查依赖边界。

## 写入与复盘

原话、原图、正式复盘和评价结果不可更新。补图、更正、修订有明确身份；改观点创建关联的新记录。普通写入使用 owner + operation + Idempotency-Key，内容变更必须换键；同键不同内容 409。用户身份来自服务器验证的 principal。

草稿独立存储，自动保存不改原判断 revision。草稿时钟保存在 call_state，发布/丢弃也推进，防止旧请求覆盖下一轮草稿。发布同时检查草稿版本、记录版本和用户实际看到的 outcome IDs；冲突不丢文字。提醒使用独立版本。复盘队列的派生状态在业务事务内同步维护，按分类和固定提交顺序建索引并分页，详情每类历史只取最新 20 条，后续通过游标读取。具体体验约定见 review-experience.md。

评价处理状态与业务结果分离：未到期、缺输入、能力缺失、供应商暂时故障都不是正式失败结果。只有完整证据支撑的计算才能发布 outcome。`outcome_heads` 唯一指明当前正式结果；data_revision 必须引用同一口径的前一正式结果，以 CAS 发布。规则回放不替换 head；固定集合保存当时统计口径和结果快照。

## 调度和资源预算

- PostgreSQL 队列使用 SKIP LOCKED；任务 identity、generation、lease owner 和到期时间共同限制发布。普通重复入队不重置任务；显式重试 CAS 推进 generation，保留尝试历史。
- API 与 worker 复用各自进程内的 HTTP 客户端和数据库池；每进程池上限 12，SQL 默认超时 15 秒。
- worker 分类预算：交互 2、历史批处理 1、维护 1。领取按用户轮转；每用户交互等待上限 200、批处理和维护各 50。跨进程执行数量通过 PostgreSQL 协调。
- API 请求并发上限 64，超载明确返回 server_busy；图像处理预算 2，Python 推理 1，批量最多 8 图。同一原图/裁剪/模型的特征计算合并进行，失败不换算法。
- Binance 请求按出口身份 `SCOREBOOK_EGRESS_ID` 和合约产品共享数据库预算，默认 600 weight/min。响应头更新观测值；429/418 的冷却传播到使用同一出口身份的进程。对新部署应根据实际出口统一设置此值。
- SIGTERM/Ctrl-C 停止领取任务；worker 最多等待 120 秒。进程丢失后靠租约及新 generation 恢复同一实现。

## 行情和检索

行情仅使用币安 USD-M/COIN-M 合约。是否存在股票相关、商品、指数等合约以真实 exchangeInfo 为准，不能把任意美股 ticker 自动映射成存在的币安合约。

原始 OHLC、aggTrades 和系统 SVG/PNG 仅在内存中存在；不得写入 DB、队列、文件、导出或日志。保存的只有用户上传原图、请求位置、规则、输入哈希、计算结果和派生向量。供应商后来订正历史时，重绘可能变化，不能承诺没有原始输入的离线逐字节重放。

私有 `image_embeddings` 按 owner 隔离。公共 `public_market.features` 仅包含行情派生数据，不保存请求用户身份。每代构建分 500 行写入；每块包含特征与代关联两次数据 INSERT，2,000 行为四块、八次数据 INSERT，另有事务/租约检查。仅发布完成代的特征；重试后弃用的旧窗口引用会在发布前剔除。

HNSW 的模型维度表达式与查询一致；使用 iterative_scan relaxed_order、ef_search 1000、work_mem 32MB、scan_mem_multiplier 4、max_scan_tuples 1000000；3,000 个候选物化后显式按距离重排，历史再取前 1,000 个做窗口去重。strict_order 在有筛选的迭代扫描中会丢掉后发现的近邻，本轮已移除该运行配置。数据库事务级共享许可最多容纳 8 个检索，满载返回 search_capacity_reached；提交、回滚或连接退出均释放许可。扫描内存预算每路约 128MB，另有排序、连接与进程开销，需要按部署资源评估。候选数量有上限，返回结果不能当作穷尽搜索。精确检索仅存在于验收脚本，用于对照召回；生产不自动退回全量精确扫描算法。数据库仍自行选择索引执行计划，需要通过 EXPLAIN 和真实负载确认。

历史计划器逐段发出任务，一个计划最多一个未完成子区间，可暂停/恢复/取消。`/v1/history/coverage` 查询公共已发布覆盖；自己的计划和索引状态另行查询。不能声称预先覆盖币安所有品种所有周期全部历史。

## 备份、删除和长期运行

v2 导出使用固定数据库快照，按约 4 MB/1,000 行分成 NDJSON，逐文件校验哈希。原图在导出期间被精确 pin，文件流复制不长期持有 DB 快照。先持久化输出身份，再原子发布；进程中断后只接受同一 v2 文件的校验身份。不会回退旧 v1 校验。

恢复先验证归档，再准备原图，用 COPY 临时表和分块合并写入一个元数据事务。恢复只面向源用户不存在的隔离目标；同一归档通过恢复回执幂等重试。归档身份标记允许从文件已发布但事务未完成的位置恢复。凭证不导入，公共行情向量可重建。原图存储有端口和本地实现，备份/恢复的工作目录仍是本地文件系统；没有宣称已经交付 S3 集群适配器。

删除根据明确的关联表清理，不在任意 JSON/原话中搜索 UUID 子串。共享原图仍被其他记录引用时保留。临时搜索默认 7 天、无引用查询图 24 小时、导出 7 天；已保存搜索保护其图片引用。GC 每次有限批次并按用户轮转，清理物理文件走维护任务，幂等写身份保留删除/过期标记。

短期会话可从当前凭证委派更小权限，过期时间不超过父凭证，父级撤销使后代失效。当前不含密码登录/OIDC、注册找回密码、云对象存储、跨区域部署或数据库角色/RLS 完整加固。提供这些端口不等于完成公网产品上线。

健康存活探测无 DB 查询；就绪探测 5 秒缓存、1 秒超时。API 日志不记录 body/query，工程指标不进入交易员页面。启动、备份和故障处理见 README 与 ops 文档。

## 验收边界

真实记录/复盘/租约/导出/恢复/本地视觉模型回归与合成负载分别验收。百万向量召回只是对精确相似度检索的对照，不是 200 张真实走势图的人类语义质量验收。2 小时生产候选部署验收需要确定目标机器和真实工作负载。

[pgvector 官方索引与迭代扫描说明](https://github.com/pgvector/pgvector#iterative-index-scans)描述了过滤、扫描预算和召回之间的约束；实际使用版本固定在 compose.yaml。
