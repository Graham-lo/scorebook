# Scorebook 独立源码产品审查 · 2026-09-12

## 方法与边界

第一轮先读当前前端源码，不读 Claude redesign / screen-map；覆盖 router/main、所有现存 features、数据适配、共享交互组件、布局与 CSS，并只读后端核实实际契约。第二轮才阅读 `scorebook-backend/docs/redesign-2026-09-12.md` 与 `screen-map-2026-09-12.md` 交叉认证。以下行号属于审查时工作树，主线程正在同步修改，最终修复后的行号会移动。没有浏览器截图或实机验证；视觉判断仅限可从 CSS 证明的结构风险。未改用户数据、未部署、未重启服务。

原则：判断当时看到什么 → 留下判断与检验方法 → 等市场给结果 → 回看自己与真实交易 → 从过去找类似经历。页面要说明事实，文字短，不能把未完成读取、局部结果或失败伪装成“没有”。

## 首批高优先级发现（已立即发给主线程）

### P1-01 搜索框合并了外形，没有合并检索语义

- 证据：`features/search/index.ts:175` 文本独立调用 knowledge.search；`run.ts:22-32` 图片独立走形态检索；`index.ts:454` 归纳只发 message，没有附件 ID 或当前结果约束。归纳在 462 行还丢弃了 citations / inference。
- 复现：放入截图，再输入“失败突破”，文字结果与图片结果各自返回；点“归纳这些记录”并不等于归纳屏幕上的这些记录。
- 影响：交易员以为正在问同一个问题，系统实际回答多个互不约束的问题；来源证据被隐藏。
- 修复：一个明确请求上下文同时包含文字、截图、确认过的品种/周期；结果保留来源和命中理由；归纳绑定本次结果/附件并呈现引用。
- 分工：主线程。

### P1-02 搜索失败与索引缺口被显示为没有结果

- 证据：`search/index.ts` 多处 `.catch(() => [])`，丢失 knowledge search coverage.pending_sources；图片不可读提示同时覆盖网络/服务错误；job 轮询失败静默持续。
- 复现：请求失败、索引尚未完成或任务停止响应，页面显示“没有找到”或一直等。
- 影响：用户对自己的历史与公共行情作出错误判断，也没有有效重试路径。
- 修复：空结果、未搜完整、请求失败分别显示一行短事实和相应操作；轮询失败可重试。主线程负责。

### P1-03 上传、识别与查询之间没有请求身份保护

- 证据：`search/index.ts:191-218` 只有页面 alive，没有文件代次；`capture/index.ts:487-503` sniff 无草稿/附件身份校验。
- 复现：上传 A 立即换 B，A 后返回覆盖 B；识别尚未完成时删图或开新草稿，旧识别污染当前草稿。
- 修复：按文件/草稿代次接收结果，过期回调不改状态；移除图同步清掉识别建议。搜索归主线程，capture 归独立审查线程。

### P1-04 记录流程的保存按钮与实际有效性不同步

- 证据：`capture/index.ts:1012-1032` 仅 paintFoot 更新 blocker；标准输入、模板与期限控件在 637、661、693 行只画 criteria / parse / context。
- 复现：选需要失效条件的模板，进第三步，补齐失效条件，按钮仍禁用；反过来清空必填内容按钮仍可点。
- 影响：最关键的写入入口被卡住，或要求用户反复点保存才知道缺什么。
- 修复：所有变更共用草稿状态刷新，按钮及禁用原因同步；原因直接可见而非只放 title。

### P1-05 草稿声称支持刷新，但仅存在模块内存；保存完成会抢走后来导航

- 证据：`capture/index.ts:5-6,179` 宣称刷新可继续；104 行 draft=blank，没有持久化。1138 起保存成功不检查用户是否已离开，1161 强制 go(new/done)。done 状态未阻止返回新建页后再次提交。
- 复现：填写后刷新，内容消失；保存中去看其他记录，请求完成把人拉回“记下了”；完成后浏览器后退可能保留已保存内容再次提交。
- 修复：持久化文字和已上传附件，说明仍在上传的本地文件不可恢复；提交保留草稿身份和幂等键，离开后只通知成功，完成后回到新建应开启空白草稿。

### P1-06 首次接账户的入口是闭环死路

- 证据：`find/fills.ts:135-173` 在 tab=accounts 分支前，connections 为空就 return 空态；`fills-book.ts:42` bookPanel 强制要求已有 connection。
- 复现：无账户 → 账单 → 接账户 → 仍显示无账户。
- 修复：accounts 页始终渲染开户表单；账户不存在时隐藏期初、导入、同步等依赖账户的表单。独立审查线程负责。

### P1-07 记录筛选把“当前页没有”当成“全部没有”，并隐藏后续数据入口

- 证据：`find/index.ts:228-248` 本地过滤无命中直接 return，分页按钮位于 261 行；方向/结果/路线/日期由本地 keep 过滤首批 20 条。结果筛选切换不主动 resolveOutcomes，未缓存详情一律 keep=false。
- 复现：首 20 条不符合方向，旧记录符合，页面仍空且不能继续找；先读列表再选“做对”会漏掉尚未读详情的条目。
- 修复：空态保留“继续查找”；明确已读条数和是否还有记录；结果筛选触发详情读取，加载/错误不冒充无结果。

### P1-08 跨页面进入记录列表可能看到另一个品种的缓存

- 证据：`find/index.ts` loaded 为全局单一布尔值；search 符号入口直接改 find.instrument/market 后 go(find)，allRecords 仅看 loaded && rows.length；keep 不检查 instrument。
- 复现：先看 BTC 记录，再从搜索点 ETH，筛选条变成 ETH，但仍展示缓存 BTC。
- 修复：列表缓存绑定所有服务端筛选条件，请求返回检查代次；条件变化重新读。

## 与既有设计交叉认证

### 已覆盖 / 当前实现偏离了设计承诺

- redesign §2.7 要求局面定义可编辑、原 playbook 能力不丢；createTag 作为更新、旧 evidence 无入口违反该承诺。
- §2.3 要求每张图自己的换图和类型管理；忽略目标图片身份是实现错误。
- §8.5 要显示同品种连续判断数量和实际成交，当前用关联个数替代记录数不成立。
- §8.7 是把历史准备移到设置，并非删除暂停/续传/取消/配额管理。screen-map §4 列明旧入口；现在等价入口缺失是功能回退。
- screen-map §3.3 已指出计数口径/截断问题；新页面继续存在不同的静默上限。此类问题非全新概念，当前具体复现是新的。
- screen-map 对完整来源、模型引用、playbook 依据选择的历史说明，支持这些功能原本存在；该历史文件不是当前实现证据，当前缺口由源码确认。

### 新增独立发现

- 保存按钮状态失配、无持久化却声称可刷新、异步保存抢导航、已完成记录返回可重复提交。
- 首账户入口闭环、结果筛选不读取详情、空态吞掉翻页、跨页面品种筛选使用错缓存。
- 已缓存行永久加载、子按钮 Enter 冒泡跳详情、上传与识别旧请求覆盖新请求、账单结果跨条件覆盖。
- 截图定位与提交时点混淆；本地服务健康被标成交易所连通；新建标签版本被当成编辑定义。

### 设计本身需要修订，不能归咎实现漏做

- §2.8 明确将同一搜索框分流至文字/标签/代码与图片结果，没有要求文字约束图片检索。最新用户要求“截图和文字搜索统一智能化”超出旧方案；需要变更请求模型，不仅改 UI。
- §6.7 明确仅识别不出周期时提供周期控件。这会阻止用户纠正识别错误，应允许识别后修改。
- §8.7 把搜索覆盖说明完全赶到设置，与“无命中可能因未索引”的真实状态冲突。应保留一行短事实和操作，无需长免责声明。
- §0.1 把 episode 解释为按品种分组，把标签和 playbook 视为同物，会丢失具体连续事件、类别定义、复盘结论采纳之间的区别。界面可合并入口，数据关联不能靠同名或品种推断。
- §8.3 有意移除 snoozed 独立桶，但没有给出撤回稍后处理的方法；这是操作可恢复性的设计缺口。
- §8.4 已推翻旧 §2.9 单屏新建方案，保留三步。三步本身不是本次问题；输入/保存/恢复不一致才是问题。§8.1 已加统计，不能引用旧导航草案要求删除它。

### 已改善、无需重复推翻

- 导航与多数文案已短化；搜索入口统一，行组件收敛三种密度，截图/关联成交模块复用。应在现结构上修行为，不回到旧页面堆功能。
- 账单导出与全量备份已区分；新建记录必须选行为路径是明确产品约定，应保留并给及时的缺项提示。
