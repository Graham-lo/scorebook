| 「去准备历史」 | 按图找 → 搜公开历史 → 底部 scope 面板 | **3** | 是 search → history 的唯一带上下文的跳转（`scope.ts:175-187`） |

| 订阅配额修改 | 公开历史 → 一直跟着做 → 停下的那一行 | **3–4** | 只在 `blocked` 时出现（`history:800-828`） |
| 归档文件列表 | 公开历史 → 合约目录 → 退市合约行 | **4** | |
| chatPanel（问答的第二入口） | 齿轮 → 下滑 | **2** | 与 `#/chat` 重复；eyebrow 在 `对着自己的记录提问` / `以后会有` 间翻转 |
| 导出备份 | 齿轮 → 下滑到 `你的记录是你的` | **2** | |
| `#/new/done` | 不可直接到达 | — | `capture:184` 强制回第一步 |
**结论性问题**：
1. `#/cycle` 是唯一一个**既在路由表里注册、又完全没有导航痕迹**的顶级路由。
2. 实盘的四个 tab 和账本维护的六块面板是全站最深的信息层（最深 5 层），但都没有 URL，无法深链、无法分享、刷新即丢。
3. 设置页承担了两种毫不相干的职责（能力清单 + 数据导出），还偷偷嵌了第三个（chat 面板）。
4. 「找过去」四种找法是平级 tab，但 recall / chat 检索同一批数据，search / history 是同一条流水线的两端 —— 真正的分类应该是"文字 / 图像"两组，而不是四个并列项。
